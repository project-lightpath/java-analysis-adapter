# PLAN-5124 — Bounded seekable ZIP metadata parser for ServiceLoader descriptor scanning

Status: implemented; gates green (see §12).
Jira: FLPATH-5124 (Dev Sub-task of FLPATH-5002).
Branch: `flpath-5124/seekable-zip`, based on `origin/main` `5d4635f`.
Confidence: **92%** after implementation and gates; see §12 for deviations.

## 0. Governing facts (verified in this worktree)

- `ServiceLoaderDescriptorArchiveSource.scan` opens `java.util.zip.ZipFile`
  eagerly (`:24`), then `enumerate` walks `zip.entries()` and applies the
  byte-denominated enumeration/retention budgets. The eager central-directory
  (CEN) index happens before any production budget applies.
- `ServiceLoaderDescriptorSource.ScanState` owns the scan-global budgets:
  decompressed 16 MiB, enumeration 2 GiB, retained 16 MiB
  (`ServiceLoaderDescriptorBudget`), plus diagnostics and WAR diagnostic caps.
- `ServiceLoaderDescriptorReader.scan` creates one `ScanState` for application
  classes, source roots, observed metadata and every dependency archive.
- `ServiceLoaderDescriptorArchiveSource` contract that must not change:
  source ordering, WAR nested-metadata diagnostics, selected-entry semantics,
  per-archive rollback, module-info/versioned-module behavior, diagnostic
  codes consumed by existing tests and by `isUnique`/certainty promotion.
- Current archive tests already cover the FLPATH-5123 boundaries that this
  change must keep green: classic 65,535 entries, 1,000,001-entry ZIP64,
  byte-budget boundaries, retention rollback, module budgets, WAR diagnostics.
- Prototype evidence at `spike/flpath-5078-prototype` `4d58edf`
  (`Spill.java`, `SeekProbe.java`, `verify.py`, `POLICY-NUMBERS.md`,
  `PERF-NOTES.md`, `prod-integration-review.md`, `review-verdict.md`).
- AGENTS.md is the process law: RED → GREEN → EVIDENCE triples, tests only in
  RED (new methods only), and the three gates after every item.

## 1. Decisions this plan makes (policy gate)

| Control | Decision | Basis |
|---|---|---|
| Enumeration count cap | None (already removed by FLPATH-5123) | heap flat to 2M entries in prototype |
| Enumeration budget | 2 GiB scan-global, unchanged | FLPATH-5123 ratified policy |
| Retained descriptor metadata | 16 MiB scan-global, `512 B` per candidate unchanged | Keeping the existing charge avoids changing four FLPATH-5123 tests; the fixed model is retained for descriptor slots |
| Retained selected names | 4 MiB scan-global **name storage** = UTF-8 bytes + 48 B String header per name, separate counter; dedup set is **per archive** | bounds the dedup strings that CEN-order retention needs; short names do not affect any existing budget test; HashSet node overhead is bounded separately by the 32,768-slot count (<= 2 MiB) |
| Decompressed payload | 16 MiB scan-global, unchanged | existing production contract |
| Per-entry materialization | **1 MiB adopted.** Selected entries whose declared uncompressed size exceeds it are skipped with `archive_entry_size_limit`; the shared 16 MiB decompressed budget still applies. | Jira expected-results set and `POLICY-NUMBERS.md`; this closes the policy gate instead of waiving it. New scan-global code, blast radius stated in the commit. |
| Raw directory I/O | 2 GiB **per archive** (prototype `rawMax`) | bounds physical CEN/header reads; separate from the semantic enumeration budget |
| Spill quota | 2 GiB **per archive**, live bytes | prototype policy; temp volume sizing documented |
| In-memory sort | 32 MiB **shared by both sorts of one archive**, disk fallback above it | two independent 32 MiB buffers would double the bound; one `BufferBudget` is shared by the selected and range sorts |
| Merge run size | 16 MiB per run | prototype disk-mode recommendation |
| Temp directory | one root per archive under `java.io.tmpdir`, POSIX 700 when supported, `deleteOnExit` plus explicit recursive delete in `finally` | prevents cross-analysis disclosure; normal-exit and success/failure cleanup; crash residue documented as residual R8 |
| Archive size | 512 MiB cap retained (`MAX_ARCHIVE_BYTES`) | avoids behavior change and unbounded SootUp-side inputs; the CEN fix does not require removing it. Residual R1. |
| Wall-clock deadline | Not added | ops-owned, prototype deprioritized; residual R3 |
| Temporary root | `java.io.tmpdir` by default, injectable config for tests | production configuration boundary; no `spike.*` properties |

The three budget scopes are deliberately different and are stated in docs:
enumeration/retention/decompression are **scan-global**; raw directory I/O and
spill are **per archive**; temp files are owned by one archive scan and deleted
in `finally`.

## 2. Compatibility matrix (documented in `docs/flpath-5124-seekable-zip.md`)

| Input | Decision | Diagnostic |
|---|---|---|
| Classic ZIP, <= 65,535 entries | Accept, full enumeration | none |
| Classic count field exactly 65,535 with 65,535 real entries | Accept; count alone is not a ZIP64 sentinel | none |
| ZIP64 with locator and consistent EOCD/ZIP64 record | Accept | none |
| ZIP64 size/offset sentinel without locator | Reject the archive, no partial descriptors | `invalid_archive` (`missing_zip64_locator`) |
| ZIP64 record bounds/count/size/offset mismatch | Reject | `invalid_archive` |
| Prefixed/SFX classic archive | Accept when CEN offset resolves through the computed prefix | none |
| Prefixed ZIP64 | Reject (prototype-strict) | `invalid_archive` |
| Encrypted entries, multi-disk, unsupported method/flag bits | Reject the archive | `invalid_archive` |
| Data descriptors (flag bit 3) | Accept, validate CRC/sizes. The two descriptor forms (optional `0x08074b50` signature, or a CRC whose value happens to equal that word) are disambiguated by validating both candidate layouts and accepting the consistent one. | none |
| Local/CEN name, flags, method, size or CRC mismatch | Reject | `invalid_archive` |
| Referenced entry ranges overlap | Reject | `invalid_archive` |
| Duplicate selected entry name | Keep the first CEN occurrence (current `TreeMap` semantics), no diagnostic | none |
| Name/comment encoding | EFS (bit 11) set: strict UTF-8, malformed input rejects the archive. EFS clear: JDK-compatible lenient UTF-8 decoding with replacement (the ZIP default legacy charset path), never an archive-level rejection. Legacy-decoded names remain selection candidates and fail the ASCII binary-name check normally. | `invalid_archive` only for malformed EFS UTF-8 |
| ZIP64 extra block | Accept every field-specific length: 8 × (length/compressed/offset sentinels present) + 4 if the disk-start field is sentinel, including a 4-byte disk-only block (then rejected as multi-disk if the value is nonzero) | `invalid_archive` when malformed |
| Selected entry declared size > 1 MiB | Skip that entry, continue the archive, release its retention slot | `archive_entry_size_limit` |
| Payload CRC | Verified only for selected entries read to EOF; ignored entries are structural only (their local header/ranges are still validated) | `archive_entry_read_error` on selected mismatch |
| Archive > 512 MiB | Reject before opening | `archive_size_limit` (unchanged) |
| Raw directory/header I/O over 2 GiB per archive | Reject the archive, no partial descriptors | `archive_raw_io_limit` |
| Spill live bytes over 2 GiB per archive | Reject the archive, no partial descriptors | `archive_spill_limit` |
| Temp spill write/read failure | Reject the archive, no partial descriptors; report the **archive** path and a sanitized detail (exception class + reason, any temp root stripped) | `archive_spill_error` |
| Temp cleanup failure after a successful scan | Best-effort delete; emit the diagnostic **without** rolling back committed descriptors (the one no-rollback spill case), never let a `finally` exception mask the primary diagnostic, leave residue for ops | `archive_spill_error` |
| Scan interrupted at a checkpoint | Roll back the current archive and stop later sources | `descriptor_scan_interrupted` |
| Truncated/unreadable file | Reject | `invalid_archive` for format, `archive_read_error` for I/O |

Strictness is intentionally higher than `ZipFile` for malformed structures
(overlap, local/CEN disagreement). That is the prototype's validated posture;
valid-archive differential parity is unchanged.

**Diagnostic blast radius:** diagnostics are scan-global
(`ServiceLoaderDescriptorScanner.isUnique` blocks DEFINITE promotion when the
list is non-empty). Adding `archive_entry_size_limit`, `archive_raw_io_limit`,
`archive_spill_limit`, `archive_spill_error` or `descriptor_scan_interrupted`
downgrades the whole scan to POSSIBLE, not just the affected archive. The
`archive_raw_io_limit`/`archive_spill_limit`/`archive_spill_error`/interrupt
diagnostics roll back the current archive and preserve earlier archives; the
size-limit diagnostic skips one selected entry and keeps earlier descriptors.
Each commit message states this blast radius.

## 3. Architecture

### 3.1 New production types (package-private)

1. `ServiceLoaderDescriptorArchiveConfig` — immutable value **class** (not a
   record, so a later field cannot break existing constructors) with
   `maxRawDirectoryBytes`, `maxSpillBytes`, `sortMemoryBytes`,
   `mergeRunBytes`, `tempRoot` (nullable = `java.io.tmpdir`), and a
   package-private `channelOpener` functional interface
   (`Path -> SeekableByteChannel`) defaulting to
   `Files.newByteChannel(path, READ)`. Construction is via `defaults()` and
   withers (`withTempRoot`, `withSpillBytes`, ...); tests never call a
   positional constructor. GREEN_2 ships the config without
   `channelOpener`; GREEN_3 adds that field and its wither. The opener is the
   deterministic mutation-injection seam; tests wrap a real channel and
   corrupt/truncate on the Nth read. No system properties.
2. `ServiceLoaderDescriptorSpill` — two-tape external merge sort plus opaque
   tapes, adapted from the reviewed prototype `Spill.java`:
   - creates one private temp directory per archive under `config.tempRoot()`
     with owner-only permissions (`PosixFilePermissions.fromString("rwx------")`
     when the file system supports it), and registers `deleteOnExit`;
   - tracks live spill bytes against `maxSpillBytes` before every write;
   - a single `BufferBudget` (32 MiB) is split into one quota per sort
     (16 MiB selected, 16 MiB ranges), so each sort flushes at its own quota
     and neither can starve the other; the quotas are not transferable, which
     keeps the bound and the finish order deterministic;
   - deterministic merge with `mergeRunBytes` runs, at most two records live
     during merge;
   - interruption checkpoints in the walk, buffer flush, merge and read loops;
   - `close()` deletes every tape and the root in `finally`.
3. `ServiceLoaderDescriptorZipDirectory` — the seekable parser:
   - EOCD tail scan, classic/ZIP64 validation, prefix computation;
   - streaming CEN walk producing `Entry(name, flags, method, crc,
     compressed, length, local, data, end)` into a visitor; no directory
     accumulation;
   - per-entry `extra()` parsing (ZIP64 field order, duplicate/absent/bounds,
     field-specific lengths including the 4-byte disk-only form), EFS-conditional
     name/comment decoding (strict UTF-8 only when bit 11 is set; lenient
     JDK-compatible replacement when clear), local header and data-descriptor
     validation with two-candidate descriptor disambiguation;
   - raw-I/O budget and seek counting;
   - `openStream(entry, state, path)` returns an `InputStream` that inflates
     raw DEFLATE (or copies stored bytes), enforces the 1 MiB cap on **actual
     produced** bytes (not only the declared size), validates
     compressed/uncompressed size and CRC at EOF, and charges only
     **unreturned** bytes produced before a `DataFormatException` (the
     prototype defect (a) fix). Exceeding either cap raises the dedicated
     `EntrySizeLimitException` so the caller can emit
     `archive_entry_size_limit` instead of a generic read error.
4. `ServiceLoaderDescriptorZipEntryStream` (may be a nested class) — the
   `InputStream` above. It never calls `consumeDecompressed` for bytes it
   returns normally: `readEntry(InputStream, state, path)` remains the single
   charging authority for returned bytes. On `DataFormatException` it charges
   `getBytesWritten()` delta not already buffered/returned, exactly once, then
   throws; the one-byte sentinel read performed by `readEntry` stays uncharged,
   preserving the existing exhausted-budget semantics.

### 3.2 Integration in `ServiceLoaderDescriptorArchiveSource`

`scan(path, descriptors, state)` keeps its signature and delegates to an
overload with `ServiceLoaderDescriptorArchiveConfig.defaults()`.

Flow:
1. Normalize, size-check (`MAX_ARCHIVE_BYTES`), record descriptor/retention
   checkpoints.
2. Open `FileChannel`; create the parser and spill context.
3. `enumerate`: stream CEN entries; for each entry apply
   `state.tryEnumerate(entryPath, centralDirectoryBytes(name, extraLen,
   comment))`, **directory skip, then WAR diagnostics** (same order as the
   current `enumerate`; the skip is what prevents a directory entry such as
   `WEB-INF/classes/META-INF/services/` from firing a WAR diagnostic).
   Retention, duplicate and selection handling happen **in CEN order**, exactly
   like the current `TreeMap`, before anything is spilled:
   - invalid binary names consume enumeration bytes but no retention and do not
     enter the selected sort;
   - a name already in the per-archive `retainedNames` set is a duplicate: skip
     silently, no retention charge, and it does **not** enter the selected sort
     (first CEN occurrence wins);
   - otherwise call `state.tryRetain(path)` (existing fixed 512 B charge,
     unchanged) followed by `state.tryRetainName(path, utf8Length(name) + 48)`
     (new separate 4 MiB name-storage budget, String header included); if
     either fails, stop immediately with `descriptor_retention_limit`, exactly
     at the same entry. Release calls return both charges;
   - only after both charges succeed, add the unique selected entry to the
     selected sort. Every referenced entry range (including ignored entries)
     goes to the range sort.
   The `retainedNames` set is **per archive** and discarded on exit (same scope
   as the current `TreeMap`), so a name in one archive never suppresses a
   descriptor in another. The name counter is scan-global (like the slot
   counter): both are snapshotted before the archive and restored together on
   the enumeration/retention failure path and in `scan`'s `finally`.
   The set is bounded in bytes: at most 32,768 candidates x 512 B (the
   existing 16 MiB slot budget), plus at most 4 MiB of name storage
   (UTF-8 + String header), plus at most 2 MiB of set-node overhead
   (64 B x 32,768). Even a 65,535-byte valid name cannot grow the set past
   that total. Existing short-name retention tests keep their exact 512 B
   accounting. Track the first root
   `module-info.class` (excluded from retention, as today) and first versioned
   module name. An enumeration or retention failure sets `complete=false` and
   restores retention, matching the current `enumerate`.
4. Finish the range sort and reject overlaps. Finish the selected sort and
   **materialize the selected entries into a bounded in-memory list** (names
   are already charged against the 4 MiB name budget and slots against the
   16 MiB slot budget; fixed record overhead is bounded by 32,768 entries,
   ~3 MiB), then close the selected sort. No spilled-record read happens during
   the payload loop, so a tape failure can only surface in the spill phase.
5. `readDescriptors`: iterate the bounded selected list in name order; stop
   with the existing `archive_decompression_limit` diagnostic when the shared
   payload budget is gone; if the declared size exceeds the 1 MiB per-entry
   limit, emit `archive_entry_size_limit`, release that entry's slot and name
   charge, and continue; otherwise open the stream and call the existing
   `readEntry(InputStream, state, path)` so charge/sentinel semantics are
   byte-for-byte the production contract; the stream's actual-produced cap
   raises `EntrySizeLimitException`, mapped to `archive_entry_size_limit`
   (not a generic read error); add the descriptor; release that entry's slot
   and name charge when no descriptor was added; release both charges for
   entries not processed.
6. `readModule`: same as today, but read from the parser stream and apply the
   same declared and actual 1 MiB checks; a size-limit failure emits
   `archive_entry_size_limit` and keeps earlier descriptors; keep the
   versioned-module diagnostic.
7. Error boundary (phase-specific, preserves current behavior):
   - **open/size phase**: `Files.size` or `FileChannel.open` failure →
     `archive_read_error` with the archive path and sanitized detail, rollback;
   - **spill phase**: `ServiceLoaderDescriptorSpill` failures from tape
     create/write/read/clear/truncate/close and from the buffered-write and
     spilled-record read-back sites are caught before the generic I/O mapping
     and reported as `archive_spill_limit` or `archive_spill_error` with the
     archive path and a sanitized detail. The same `sanitizedMessage(error,
     tempRoot)` helper is applied at the archive-scan boundary to **every**
     archive-level diagnostic detail (`invalid_archive`, `archive_read_error`,
     `archive_size_limit`, `archive_raw_io_limit`, `archive_spill_*`), stripping
     the temp root and any child path. A temp path never reaches a scan-global
     diagnostic;
   - **structural phase** (EOCD/ZIP64/CEN/local-header/data-descriptor
     validation, prefix, overlap, unsupported method/flag/encryption,
     enumeration or retention incompleteness): our format exception →
     `invalid_archive`; other `IOException` → `archive_read_error`; rollback.
     Unsupported method/flag/encryption is **only** in this phase because it is
     detected from the CEN record before any payload read;
   - **selected-payload phase**: stream decompression, actual/declared size
     limit, compressed/uncompressed size mismatch or CRC mismatch →
     `archive_entry_read_error` (or `archive_entry_size_limit`), release that
     entry's charge, continue with the next selected entry, keep earlier
     descriptors (same as today's `addDescriptor`);
   - **module-payload phase**: stream read failure →
     `archive_entry_read_error`; size limit → `archive_entry_size_limit`;
     keep earlier descriptors and return `true` (same as today's `readModule`);
   - **sentinel-time failure**: the single uncharged `readEntry` sentinel read
     can raise a stream exception after the budget is exhausted; it is caught
     by the same selected/module payload handling, the already-returned bytes
     stay charged, no descriptor is added, and the sentinel byte itself is
     never charged;
   - **cap precedence at the budget boundary**: if the shared decompression
     budget is exhausted before the entry reaches 1 MiB of produced bytes,
     `archive_decompression_limit` wins (the sentinel returns a byte); if the
     entry itself crosses 1 MiB, `archive_entry_size_limit` wins (the sentinel
     read raises `EntrySizeLimitException`). Both are deterministic and are
     tested at remaining budget = 1 MiB - 8 KiB, exactly 1 MiB, and 1 MiB + 1;
   - interruption → `descriptor_scan_interrupted` (new scan-global code,
     commit message states the whole-scan certainty blast radius), rollback
     this archive, clear the interrupt only after cleanup, and stop the
     remaining source loop in `ServiceLoaderDescriptorReader.scan` after one
     diagnostic.
8. `finally`: rollback descriptors and retention unless complete; close the
   parser and spill so temp files are removed on every path. Cleanup is
   best-effort and cannot mask a primary failure: a delete/close exception is
   caught, reported as `archive_spill_error` with the archive path and a
   sanitized detail, and does **not** roll back already-committed descriptors
   on the success path (the one explicitly documented no-rollback spill case).
   Any residue is owner-only and named `flpath-5124-spill-` for ops cleanup.

`ServiceLoaderDescriptorBudget` gains
`centralDirectoryBytes(String name, int extraLength, String comment)` with the
same formula/floor as the `ZipEntry` overload; the old overload stays for
directory/other callers and tests. `ScanState` gains a 4-argument
`withBudgets(maxDecompressed, maxEnumerated, maxRetained, maxRetainedNameBytes)`
overload (the existing 3-argument form delegates with the 4 MiB default), plus
`tryRetainName`, `releaseRetainedName`, and a `RetentionSnapshot` record with
`retentionSnapshot()` / `restoreRetention(snapshot)` so slot and name counters
roll back together. No existing signature changes.

### 3.3 Preserved semantics (explicit)

- Selected service entries: prefix `META-INF/services/`, non-directory,
  valid binary class name; sorted by full entry name (String natural order),
  first duplicate wins.
- WAR: one diagnostic for the first skipped nested metadata, one suppression
  diagnostic thereafter, keyed by `archive!/name`.
- Module: root `module-info.class` read after descriptors; versioned-only
  archive emits `versioned_module_info_unsupported`.
- Rollback: enumeration or retention incomplete, structural format error, or
  archive-level I/O error → no descriptors from this archive and no module;
  earlier archives untouched. Selected-entry and module-payload failures are
  **not** archive-level: they keep earlier descriptors from the same archive,
  release only that entry's retention charge, and continue, exactly like the
  current `addDescriptor`/`readModule`.
- Decompression exhaustion mid-archive keeps earlier descriptors
  (`decompressionExhaustionMidArchiveKeepsEarlierDescriptors`).
- Paths in descriptors/diagnostics remain `archive + "!/" + name`.

  `invalid_archive`/`archive_read_error`, rollback, cleanup; a rename-replaced

- sort-quota interactions: direct `ServiceLoaderDescriptorSpill` tests with

  selected name (one retention charge) produces one descriptor and a bounded

- boundedness probe additions: N long-name descriptors where
  `N x (512 + 64) <= 16 MiB` and `N x (nameBytes + 48) <= 4 MiB` (for example

`SeekableZipBoundednessProbe` (test-source utility, tagged large-archive or a

## 9. Residuals (planned)

- R1: `MAX_ARCHIVE_BYTES = 512 MiB` retained; a > 512 MiB archive is still
  rejected before open. The CEN fix does not remove this separate cap.
- R2: the 1 MiB per-entry control is a declared-size check; a lying DEFLATE
  size still terminates at the shared 16 MiB decompressed budget and the
  stream's size/CRC check.
- R3: no wall-clock deadline; ops-owned per `POLICY-NUMBERS.md`.
- R9: no tenant/analysis aggregate spill quota. `ServiceLoaderDescriptorReader`
  scans archives sequentially, so at most one spill root is live per analysis;
  concurrent analyses are bounded by the caller's concurrency. Ops sizing
  (2 GiB × concurrent analyses) is documented in the evidence doc.
- R8: a JVM crash (not an exception) can leave one owner-only spill root under
  the temp directory; `deleteOnExit` covers normal exit, `finally` covers
  success/failure/interrupt. Crash residue is documented for ops cleanup by the
  `flpath-5124-spill-` prefix. No cross-process deletion is attempted.
- R4: scan-global enumeration/retention budgets remain cumulative volumes, not
  live peaks (FLPATH-5123 property).
- R5: prefixed ZIP64 remains unsupported (prototype-strict).
- R6: malformed-archive strictness is higher than `ZipFile`; documented.
- R7: SootUp's own archive class-loading path is unchanged by design.

`docs/flpath-5124-seekable-zip.md`.

  natural order differs for non-ASCII names between JDK runtimes; directory
  candidates now order by file name then path. Both JDK 17 and 27 suites green.

  `maintainability` findings (complexity/GodClass) and 5 intentional

- **Boundedness probe is manual**, not a JUnit test: 1M entries at `-Xmx128m`,
  peak heap 80.8 MB, RSS 161.6 MB, 0 diagnostics, 1 descriptor.
